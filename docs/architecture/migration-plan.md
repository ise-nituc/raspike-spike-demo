本PRは調査・設計のDraft。既存コード、README、systemd、sudoers、ネットワークを変更せず、実機操作も行わない。以下の段階はレビュー後に個別PRで実施する案であり、今回の作業として実施したものではない。

## 2. 教員が行う実機棚卸し（今回は未実施）

最初にモーター停止・機体占有を確認し、読取り中心で次を記録する。古いコピーを消す前に内容を退避し、robot/との差分を確認する。

- リポジトリ/SDK/submoduleのコミット、dirty状態、実行ユーザーHOME、コンパイラ版、OS/arch。
- workspace内のappdirの型と内容、同名アプリディレクトリ、旧マーカー、シンボリックリンクの参照先。SDK外での未回収編集の有無。
- 導入済みunitとテンプレートとの差、enable状態、sudoの解決先と許可範囲、aspの所有者/権限/版。
- カメラ・TCP・ポート競合、PID管理スクリプトとの混用、フォース/カラー/モーターポート。
- AP/有線/校内Wi-Fiの実状態、SSIDと機体ID、DHCP、経路、PC側設定と回復手段。

現行build-robotには旧コピーを削除する処理があるため、棚卸し前に「確認のため」として実行しない。SDKのmakeとsudo起動の内容を読み、必要なら機体ごとのテスト用配置で検証する。

## 3. 実機検証マトリクス

| ケース | 測定・確認するもの | 合否判断 |
| --- | --- | --- |
| 3アプリのcold build/cache hit、アプリ間切替 | ソース版・asp digest・起動対象、成功/失敗ログ、所要時間 | 想定成果物だけが起動。失敗後は旧aspを実行しない |
| 直接make混在/複数checkout/連打 | ロック・拒否・待機・取消し・状態遷移 | 機体単位で一実行。遅延した要求が予期せず後から走らない |
| force操作、停止ボタン、Ctrl+C、SIGKILL | 指令停止から車輪停止まで、再始動条件 | 教員がコース速度から定めた最大停止距離/時間以内。プロセス終了だけで合格にしない |
| ブラウザ切断/タブ閉じ/再読込/PCスリープ | lease失効、モーター停止、保存/ビルド保持 | 自動再走行なし。再接続してrevision/job結果取得 |
| Web停止、worker停止、Pi再起動 | 独立監視と実行unitの状態、復旧時の動作 | 停止側に復帰し、明示操作前に走らない |
| Python停止/recv無応答/カメラ更新停止 | TCP期限と指令鮮度の停止時間 | 固定PWMが残り続けず停止。既存pause/検出失敗停止を弱めない |
| 不正C/無限ループ相当/ビルドハング | 入力拒否、時間上限、停止経路の優先、子プロセス残留 | 停止要求がロック待ちしない。手元の停止方法が機能 |
| 多台数AP/有線/校内Wi-Fi | 接続時間、切断率、再接続時間、誤機体接続、往復遅延 | 機体識別を誤らず40分進行を完走。電波品質は現地で判断 |
| 復元/ディスク不足/保存競合 | 退避版、atomic保存、revision、ビルド無効化 | 編集を失わず旧版を誤実行しない。main/配布版が不変 |

heartbeat 0.5秒/失効2秒は検討用の初期値に過ぎない。走行速度×失効時間に制動距離を加えて、コースの余裕に収まる値を決定する。ソフトウェアで停止保証ができない故障は物理的な停止方法・運用制限で扱い、教材を走行に使わない判断も残す。

## 4. 設計レビューで決める事項

robot/正本、共通管理入口、有線標準、制限Webエディタという方針を確認する。次に、採用SDK版とroot要件、停止手段/最大停止距離、許可教材語彙、初期/完成テンプレート、機体ごとの担当者を確定する。その後に実装PRを起こす。本Draftの作成を実装開始・mainマージの承認とは解釈しない。
