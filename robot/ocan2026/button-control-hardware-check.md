# 第2回オープンキャンパス：学生スタッフ用・実機確認手順

この文書だけで、**準備 → ビルド → 車輪を浮かせた動作確認 → 結果報告**まで進められます。教員の都度の許可・返信は不要です。Gitの難しい操作も不要にしています。

対象は小型のLEGO製ロボットです。ただし、車輪・配線の巻き込みや落下、制御不能時の予期しない走行を避けるため、**初回は2人1組・車輪を浮かせた状態**で確認します。

> **この手順で自分たちで進めてよい範囲**：既存環境の調査、別フォルダへの試験用コード取得、ビルド、通常のボタン動作、前進・左右・停止、通信断テスト（いずれも車輪を浮かせた状態）。
>
> **この手順では行わないこと**：床面での自由走行、故障を意図的に起こす試験（無限ループ、USB抜去、割込み停止など）、OS・ネットワーク・systemd設定変更。これらは別途計画して実施します。
>
> ボタン制御はPR #21の**実装候補**です。実機で正しく動くことはまだ確認できていません。失敗や疑問があれば、無理に修正せず、結果をTeamsに報告すれば十分です。

## 0. 最初にすること

1. **2人で作業**してください。1人はPC操作、もう1人はロボット・周囲・停止操作を担当します。
2. ロボットを倒れない台に置き、**両車輪が床や机に接触しない状態**にしてください。
3. SPIKE Primeの**電源を切る方法**を確認し、操作できる位置に人を配置します。フォースセンサーはソフトウェアのボタンなので、通信やプログラムが固まったときは効かない可能性があります。
4. 今使っている別のデモ・プログラムが動いていないことを確認します。何が実行中か判断できなければ試験せず報告してください。
5. これから実行するコマンドは**Raspberry Piのターミナル**で実行します。コマンドを一行ずつコピーして入力してください。

## 1. 現在の環境を確認する（変更しない）

次を実行し、画面をコピーするかスクリーンショットを保存してください。ファイルがないという表示は、そのまま報告すれば構いません。

```bash
hostname
cat /etc/raspike-id
git -C ~/raspike-spike-demo status -sb
git -C ~/raspike-spike-demo log -1 --oneline
git -C ~/RasPike-ART rev-parse --short HEAD
git -C ~/RasPike-ART submodule status --recursive
ls -ld ~/RasPike-ART/sdk/workspace
```

**元の `~/raspike-spike-demo` は変更しません。** `git pull`、`git checkout`、`git reset --hard`、`git restore` は使わないでください。Gitの仕組みを理解する必要はありません。

### ビルド前の重要な確認

現行のビルドスクリプトには、以前の方式で作られたSDK workspace内のコピーを削除する処理があります。そのコピーに作業が残っていないことが不明な機体では、ビルドを実行しないでください。まず次を確認します。

```bash
ls -la ~/RasPike-ART/sdk/workspace/ocan2026 2>&1
cat ~/RasPike-ART/sdk/workspace/ocan2026/.raspike-spike-demo-source 2>&1
```

`ocan2026` ディレクトリが存在する、あるいはその内容や表示がよく分からない場合は**ビルドをいったん中止して結果を報告**してください。存在しない場合は次へ進めます。

## 2. PR #21のプログラムを専用フォルダに取得する

既存の作業を壊さないよう、別のフォルダを使います。**最初の一回だけ**、次を実行してください。

```bash
cd ~
git clone --branch feature/ocan2026-force-button --single-branch https://github.com/ise-nituc/raspike-spike-demo.git raspike-ocan21-test
cd ~/raspike-ocan21-test
git log -1 --oneline
git status -sb
```

`raspike-ocan21-test` が既に存在するというエラーが出た場合、**削除せず**、作業を止めてその旨を報告してください。別の人の変更が残っているかもしれません。

`git log` に表示された短い英数字を報告してください。PR #21のソースであることを判断するためです。

## 3. 最初のビルド（走行はまだしない）

SDK workspaceに旧コピーがないこと、別のロボットプログラムが動いていないことを確認してから実行します。

```bash
cd ~/raspike-ocan21-test
scripts/build-robot ocan2026
echo "build exit code: $?"
```

- `build exit code: 0` ならビルドの終了コードは成功です。表示ログも保存してください。
- `0` 以外やエラー表示なら**そこで中止し、ログを報告**してください。以前の `asp` が残っていても実行しません。
- 既存のキャッシュが利用された場合は `cache hit` と表示されることがあります。ログにそのまま記録してください。
- SDKを更新したり、キャッシュやworkspace内のファイルを自分の判断で削除したりしないでください。

## 4. 車輪を浮かせたままボタンの試験

2人がそろい、停止担当が電源に手を届かせられる状態で行います。

実行中の別プログラムがないことを確認してから、以下で起動してください。

```bash
cd ~/raspike-ocan21-test
scripts/start-robot ocan2026
```

このコマンドは起動前に再ビルド・キャッシュ確認もします。**Webダッシュボードから同時に起動しないでください。** 今回はCLIによる動作だけを試します。

**注意：試験を始める前に、次の操作を読んでください。** 試験はすべて車輪を浮かせた状態で行います。

| 順番 | 行う操作 | 正常な場合 |
| --- | --- | --- |
| 1 | 起動後、ボタンを押さずに待つ | `WAITING`、車輪は停止 |
| 2 | フォースセンサーを1回押して離す | `RUNNING`、車輪が回る |
| 3 | もう1回押して離す | `PAUSED`、車輪が止まり、その状態を保つ |
| 4 | もう1回押して離す | `RUNNING`、再び回る |
| 5 | ボタンを長押しする | 押し続けても何度も切り替わらない |
| 6 | 一度終了し、ボタンを押したまま起動する | 押しっぱなしでは走り始めず、離して押し直すと開始 |
| 7 | 短く押す・少し速く押す | 意図しない連続切替を起こさない。短すぎる押下は無視されてもよい |

一時停止中は数秒以上観察し、勝手に再び回り出さないか確認してください。停止までの時間や、惰性による回転があれば記録します。**ログに `PAUSED` と表示されても、実際の車輪が止まったことを必ず確認**してください。

問題があればその場で終了し、機体の電源を切るなどして安全を確保します。以後の走行試験は行わず、ログと症状を報告してください。

## 5. 前進・左右・停止の確認（余裕があれば）

こちらも**車輪を浮かせた状態のみ**で行います。まずプログラムを終了し、車輪が止まったことを確認してから編集します。

`~/raspike-ocan21-test/robot/ocan2026/app.c` を開き、`tracer_task()` 内の `if/else` の部分だけを `forward();` に置き換えてください。`(void)unused;` と `ext_tsk();` は残します。

変更後は「3. ビルド」「4. 試験」の手順で再確認します。同じ手順で `left();`、`right();`、`stop();` も1つずつ試せます。

`left()` は左の車輪が遅く、`right()` は右の車輪が遅くなる設計です。方向の細かな確認は床面走行の別試験で行います。

編集や保存方法が分からなければ、この節は飛ばして構いません。

## 6. Wi-Fiを切断した場合（余裕があれば）

**車輪を浮かせ、機体のすぐ横に停止担当がいる状態**で実施してください。

1. プログラムが動いている状態で、PC側のWi-Fiを一時的に切断するか、ブラウザを閉じます。Piのネットワーク設定は変更しません。
2. これだけでは走行を停止させない設計です。その間も**機体側ボタンで一時停止・再開できるか**を確認してください。
3. 再接続しても自動再起動せず、動作が二重にならないことを確認してください。

SSHで試験プログラムを起動している場合は、**Wi-Fi切断でSSHセッションや実行プロセス自体が終了する可能性があります**。この場合は「CLI切断で試験不能」と記録し、無理に繰り返さないでください。本格的な通信断試験は、Web/systemd経由の独立起動環境が整ってから再実施できます。

## 7. 終了方法と中止条件

通常は、起動した**同じターミナル**で `Ctrl+C` を押して終了します。**プログラム終了と車輪停止を別々に確認**してください。止まらなければ、操作担当は追加コマンドを試さず、停止担当が確認済みの物理的方法で止めます。

以下の場合、**その日の走行試験は終了**してTeamsに報告してください。

- ボタンを押しても停止しない／停止後に勝手に回る
- `ERROR` 表示、ビルド失敗、想定外のプログラム起動
- 電源・USB・機体の動作が不安定、異音、異常な発熱
- GitやSDKの状態が分からない、別の学生の編集が残っている
- 停止方法が分からない、2人で安全を確保できない

**無限ループの試験、USBを抜く試験、OS設定変更、床面での自由走行はこの手順に含めません。** 次の段階で必要なら別途案内します。

作業を終えたら、使用した `raspike-ocan21-test` フォルダは**消さずにそのまま残して**ください。ソースを元へ戻すためのGit操作は不要です。
